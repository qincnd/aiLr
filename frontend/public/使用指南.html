01能做什么 / 不能做什么

aiLr 是一套「网页 + Python 后端 + Lightroom Classic 插件」的本地调色工作台，链路是：

网页上传照片/RAW → 视觉模型读图并给出受约束的 Develop 参数
      → 网页可逐项微调 → LrC 插件把参数写入当前选中照片
      → LrC 真正渲染 → 回传网页预览，或按选项导出下载

能做到

  • 支持常见 RAW（DNG、CR2/CR3、NEF/NRW、ARW、RAF、ORF、RW2、PEF 等），解码后只用预览做分析，原片不改写。
  • 网页「全部 LrC 调色参数」面板把 107 项 Develop 参数按 LrC 面板分组列出：左侧开关表示「是否允许大模型调整该参数」，默认除 19 项实验参数外全部打开；行末的 ＋ 可把该参数以当前值手工加入本次渲染，不必依赖 AI 建议，拖动滑块或下拉选择即可微调。
  • 「应用到 LrC 并预览」拿到 Lightroom 真实渲染结果（2560px JPEG），而不是网页伪造效果。
  • 「LrC 渲染并下载」按 JPEG / PNG / TIFF、JPEG 质量与最长边导出成品；「导出调色参数 .JSON」保存参数快照。
  • 本地 Ollama 或任意 OpenAI-compatible 视觉模型二选一，密钥只留本机。

做不到 / 需要注意

  • 插件通过 LrDevelopController 接入的是 Develop 面板的滑块/开关/枚举类参数（含 HSL 混色器、颜色分级、分离色调、点曲线、细节、暗角与颗粒），蒙版、局部调整、瑕疵修复、裁剪与镜头配置文件本身仍无法通过接口写入，这些请照旧在 LrC / PS / Lr 里做。
  • 镜头校正与变换两组共 19 项与 LrC 版本、镜头配置文件相关，标记为「实验」；被当前宿主拒绝时只会跳过该项并在网页给出黄色提示，不会让渲染失败。
  • 网页不模拟 Lightroom 的像素效果，也没有「实时预览调色结果」；要看效果必须由 LrC 渲染回传（即 preview 流程）。
  • 预览与导出都会改写当前照片的 Develop 设置并产生可撤销的历史记录，建议用副本 / 虚拟副本做试验。
  • 一键脚本不会自动安装 Ollama，也不会替你执行 ollama serve；也不会替你安装 LrC 插件。

02三步上手

  1. 初始化（只需一次）：在项目根目录双击 init.bat（等价于 scripts\init.ps1）。它会创建 .venv、安装后端与前端依赖、由 .env.example 生成 .env，并检查 Ollama 与默认模型。
  2. 启动服务：双击 start.bat。后端与前端各自开一个窗口，健康检查通过后自动打开浏览器 http://127.0.0.1:5173。
  3. 开模型 → 出方案 → 交 LrC：右上角「模型设置」里点「保存并启动」；上传照片、写下调色意图、点「生成调色方案」；确认 LrC 中选中同名照片后点「应用到 LrC 并预览」。
第一次联动 LrC 需要先装插件并启动桥接，见第 07 节。停下服务只需关闭标题为 aiLr backend / aiLr frontend 的窗口，或在窗口里按 Ctrl+C。

本地模型权重

ollama pull qwen2.5vl:7b

默认模型 qwen2.5vl:7b，推理上下文 8192 tokens（比 Ollama 常见的 4096 更吃内存）。启动 aiLr 不会自动加载模型，只有模型设置里的「保存并启动」才会加载。

05模型设置

点击右上角「模型设置」，二选一：

  • 本地模型（Ollama）：打开时会读取 /api/tags 列出已下载模型（只读清单，不加载模型），下拉选择即可；改过地址请先「保存配置」再「重新检测」。
  • 云端模型：填写模型 ID、API Base URL、API Key；任何兼容 Chat Completions + 图像输入 + JSON 输出的服务都可以。

两个按钮的区别很关键：

  • 「保存配置」只写配置，不启动模型。
  • 「保存并启动」才会加载本地模型或校验云端连通性；运行中可点「停止」卸载本地模型。
  • 切换 provider / 模型后必须重新「保存并启动」，否则生成建议会被拒绝。
配置以 JSON 保存在 backend/data/model_config.json，其中的 API Key 是本机明文（该文件已加入 .gitignore，不要提交或同步到公开位置）。选择云端 provider 时，照片会被发送到你所配置的云端服务。

06网页调色流程

  1. 选照片：把照片拖进画布或点选文件。普通图片上限 12 MB，RAW 上限 100 MB（可用 .env 里的 AILR_MAX_IMAGE_MB / AILR_MAX_RAW_IMAGE_MB 调整）。RAW 由后端按相机白平衡解码，并生成最长边 ≤ 2048px 的 JPEG 供网页显示和模型分析，原片不会被改写。
  2. 写调色意图：例如「自然通透，保留天空层次，绿色不要过饱和」。可以写具体描述，也可以留空让模型自行判断。面板右上角的「调色预设」会从右侧滑出抽屉，内置 8 个中文调色方向（胶片暖调人像、自然通透风光、日系清新、电影感青橙、黑白纪实、复古暖褐、冷调高级灰、暗调情绪）；点卡片即把整段提示词填入输入框并关闭抽屉，之后仍可继续改写，按 Esc、点遮罩或点右上角 × 也能关闭。当前输入与某个预设完全一致时，卡片会标注「已填入」。
  3. 生成调色方案：网页会把「允许大模型调整的参数集合」一起发给后端，模型以资深调色师的工作流作答（先读图诊断 → 先修影调与白平衡 → 再塑形与配色 → 最后细节与效果，且本插件只有全局滑块，不会承诺蒙版或局部调整），并按「基础滑块 + 按 LrC 面板分组的触发条件」返回一段中文说明 + Develop 参数（按需要 3–12 项，允许集合较小时该区间会自动收窄；默认允许集合为除实验参数与蒙版（效果面板的裁剪后暗角五项，默认关闭）外的全部 83 项，涵盖数值、枚举、开关与点曲线）。模型若给出未允许的参数名，或超出范围／枚举取值、类型不对的参数，后端会先把溢出清单连同原答案回传给模型，要求它在范围内重新作答（默认最多 2 轮）：修好的参数正常采用，仍未通过校验的参数会被丢弃并在面板上给出黄色提示，因此写进 LrC 的值一定在范围内；若所有参数都越界，网页会直接报错并建议重新生成（详见第 09 节）。暗角还多一层「伪蒙版」护栏：裁剪后暗角若会被画成画面上的一圈硬边圆形（圆度为正 + 羽化过低 + 数量拉满），同样会被打回重答，模型坚持不改时按安全窗口收敛（数量 ±60、羽化 ≥ 25、圆度 ≤ 25、中点 20–80、样式不用「绘制叠加」），每条改动会列在提示条的「已按防伪蒙版规则收敛」里；蒙版默认关闭，只有先在「参数微调」最上方的蒙版开关条里打开，暗角参数才会参与本次请求；网页手动拖动、插件与 MCP 不受这条限制。
  4. 检查并微调：「参数微调」标题下方是蒙版开关条——左侧总开关默认关闭（关闭时 AI 不会给出暗角参数，已加入的暗角值也会被移除），右侧 关闭 / 轻 / 中 / 强 按钮可一键把裁剪后暗角设为 -15 / -30 / -50（同时写入羽化 60、圆度 0、中点 50、样式 1，不会画出圆形硬边），之后仍可手动微调。右侧列出本次要写入 LrC 的全部参数，数值为滑块、枚举为下拉、开关为勾选框、点曲线为 x,y;x,y 文本框；每个参数右侧的 × 可把它从本次渲染中移除。步进由参数决定（曝光 0.05、色温 50、锐化半径 0.1，其余为 1）。往下是「全部 LrC 调色参数」面板，按 LrC 面板分区列出全部 107 项：左侧开关 = 是否允许大模型调整该参数（默认除实验参数与蒙版外全部允许），关掉某个开关时该参数也会退出本次渲染；行末 ＋ = 以当前值把参数加入本次渲染，加入后可直接拖动或下拉改值，再按 × 移除。
  5. 应用到 LrC 并预览：插件切到 Develop 模块、写入参数，再用 LrExportSession 渲染 2560px JPEG 回传网页；预览区会多出「原图 / LrC 渲染」切换。
  6. LrC 渲染并下载：选择 JPEG / PNG / TIFF，JPEG 可调质量（50–100，默认 92），最长边可设 256–12000 px（默认 6000），成品由浏览器直接下载。
  7. 导出调色参数 .JSON：把当前参数与说明存成 *-develop.json，便于留档或手工复现。
第 5、6 步都要求插件已连接且 LrC 选中与网页同名的照片，否则按钮不可用或直接提示失败。

07与 Lightroom Classic 联动

首次接入（只做一次）

  1. 启动 LrC，打开「文件 > 增效工具管理器」，点「添加」。
  2. 选中项目根目录下的 aiLr.lrplugin 文件夹本身（不要进入文件夹选里面的文件，也不要选项目根目录）。列表里应出现 aiLr Lightroom Bridge，状态为已启用。
  3. 切到「图库」模块，在菜单栏最右侧点击 aiLr: Start/Stop Web Bridge 启动轮询。启动弹窗会显示版本号与参数数量，例如 Bridge started (2026.09.28.1) with 107 develop parameters. ...。
  4. （建议）回网页在「全部 LrC 调色参数」面板点一次「检测 LrC 支持」，让插件用只读方式自检当前 LrC 版本接受哪些参数；不支持的会被置灰。该操作不会修改照片。
  5. 回网页，确认右下角 / 底部显示 LrC 已连接且文件名与你上传的照片一致。
插件目录名必须以小写 .lrplugin 结尾。仓库里只保留一份 aiLr.lrplugin，不要再复制改名（历史故障：副本被命名为 lrc-plugin.Irplugin，大写 I，LrC 直接拒绝添加，而且副本里的清单会和主目录不同步）。

改过插件代码之后

Bridge.lua 等文件被修改后，必须回到「文件 > 增效工具管理器」选中该插件点重新加载，或者完全重启 LrC；否则 LrC 执行的一直是内存里的旧代码。判断方法见第 09 节的版本号排查。

运行规则

项目行为
照片匹配网页与 LrC 必须选中同名照片，否则网页拒绝创建任务（HTTP 409）。

渲染失败的完整原因会由插件回传到网页，红条里以 aiLr Bridge 版本号: 原始报错 的形式显示，排查时先看这个前缀。

参数值分四类：数值（滑块，步进由参数决定：曝光 0.05、色温 50、锐化半径 0.1，多数为 1）、枚举（白平衡预设、曲线预设、暗角样式、Upright 模式，下拉选择）、开关（转换为黑白、删除色差、启用配置文件校正、自动调整色调）、点曲线（文本框，写法 0,0;64,52;128,132;255,255，2–16 个控制点且 x 必须递增）。默认允许大模型调整的集合包含这四类（蒙版即效果面板的裁剪后暗角五项，默认关闭，需要在最上方的蒙版开关条里打开才会交给 AI），模型也可能直接给出枚举名、开关值或点曲线（点曲线以 x,y 字符串返回，后端会还原成控制点表）。

蒙版与局部调整（渐变、径向、画笔、主体 / 天空选择）、瑕疵修复、裁剪与旋转、镜头配置文件本身、直方图与色阶不在 LrC 插件接口范围内，仍请在 LrC 里完成。

「实验」两组共 19 项与 LrC 版本、镜头配置文件相关，默认不允许大模型调整（不会进入该次请求的参数字段）；需要时可在面板里手动打开它们的开关为该次请求解锁，或用行末的 ＋ 直接加入本次渲染；被宿主拒绝时只跳过该项。点「检测 LrC 支持」可让插件用只读的 LrDevelopController.getValue 逐项自检，不支持的参数会被置灰——该操作不会修改照片。

色温属于「白平衡」类参数：LrC 中照片若处于「原照设置 / 自动」白平衡，写入数值会切换到自定义色温，肉眼变化可能较明显，建议在虚拟副本上试。

09常见问题排查

点击展开每一条，按「现象 → 原因 → 处理」执行。

生成调色方案时看到黄色「参数越界」提示，或红条报「参数全部越界」

现象：建议说明下方出现黄色提示条（例如「模型首次回答有 2 项参数越界，已把溢出清单回传并修正 1 次」），或直接红条报「生成建议失败: 模型返回的参数全部越界」。

原因：模型的每个参数都会按 backend/app/settings.py 的注册表校验（键名白名单 + 数值范围 + 枚举取值 + 曲线控制点）。视觉模型偶尔会给出超出滑块范围的值，或使用枚举表之外的写法（例如把色温写成 0.5、把白平衡写成 Sunny）；Lightroom 会拒绝这些值，所以后端不会把它们写进照片。

处理：①后端发现越界后会把溢出清单连同模型刚给的原答案一起回传，要求它在范围内重新作答，默认最多 2 轮；修好的参数照常进入方案，提示条里会写明修正了几项。②仍未通过校验的参数会被丢弃，并逐条列在提示条的「查看越界参数明细」里，本次渲染不会带上它们，可以按范围手动补一个值。③若全部参数都越界，网页直接报错；换一个模型或把调色意图写得更具体后重新生成即可。

LrC 渲染里出现一圈奇怪的圆形「蒙版」/ 硬边圆环

现象：预览里的照片上出现一圈明显的圆形边界，圆内圆外亮度不同，看起来像有人加了一块径向（圆形）蒙版。

原因：插件只会写全局滑块，不会创建蒙版或局部调整，网页本身也不做像素合成；画面上能出现圆形的只有「效果 → 裁剪后暗角」这一组参数——圆度为正会把暗角画成画面里的圆（横构图左右两侧就会露出一圈弧线），羽化接近 0 会留下硬边，数量拉满则变成一圈明显的光晕/黑圈。

处理：①蒙版（裁剪后暗角）默认关闭，先在「参数微调」最上方的蒙版开关条里打开才会使用，因此这条排查多半在打开了蒙版、或手动加了暗角参数时才会遇到；打开后模型链路还有护栏：这类暗角值会和越界参数一样被打回模型重答，模型坚持不改时按安全窗口收敛（数量 ±60、羽化 ≥ 25、圆度 ≤ 25、中点 20–80、样式不用「绘制叠加」），提示条里会列出每条改动。②想自己判断来源，点画布右上角的「原图 / LrC 渲染」切换：原图里也有这个圆说明它是照片本身的镜头眩光/光斑（脏镜头、滤镜或对着太阳直拍都常见），滑块改不掉；只有 LrC 渲染里才有就是暗角参数造成的，把蒙版关掉（或点强度里的「关闭」）再重新生成即可，也可以手动把「暗角 圆度」拖回 0、「暗角 羽化」拉到 25 以上。③手工拖动、插件与 MCP 不受护栏限制，故意做圆形暗角仍然可用。

网页一直显示「插件未连接 / 等待 Lightroom Classic 插件连接」

原因：插件没启动、被 LrC 卸载、或超过 15 秒没有心跳；也可能是后端没跑。

处理：①确认 http://127.0.0.1:8000/api/health 能打开；②LrC「图库」模块点一次 aiLr: Start/Stop Web Bridge（若上次是运行中退出的，第一次点击可能是停止，再点一次启动）；③确认插件在「增效工具管理器」里已启用；④确认 LrC 有选中照片，空选也会导致文件名上报为空。

点「应用到 LrC 并预览」提示 LrC 选中的是别的照片

原因：网页上传的照片文件名与 LrC 当前选中照片不一致，后端返回 409 并拒绝创建任务。

处理：在 LrC 里选中与网页同名的文件（扩展名不用一致，比较的是完整文件名）；改名过的副本请重新选择，或改用未改名的原文件。

红条报 Yielding is not allowed within a C or metamethod call

原因：旧版插件把会 yield 的函数（LrHttp.get/post、LrTasks.sleep、LrApplicationView.switchToModule、LrExportSession:renditions() 迭代）放进了标准 Lua 的 pcall；它是 C 调用边界，内部禁止 yield。

处理：当前 Bridge.lua 已改用 protected_call（优先 LrTasks.pcall，无该 API 时用协程转发 yield）。出现这条报错说明跑的是旧代码，请重新加载插件或重启 LrC。自己写插件代码时不要用裸 pcall/xpcall 包裹会 yield 的函数。

红条报 attempt to call field 'remove' (a nil value)

原因：Lightroom 的 Lua 沙箱删掉了标准库里所有会改动文件系统的函数，插件里 os.remove 的值就是 nil（同类还有 os.rename、os.tmpname、os.execute、io.popen）。这不是拼写错误。

处理：当前 Bridge.lua 已改用 SDK 的 LrFileUtils.exists + LrFileUtils.delete 清理临时渲染文件，并且失败也不会让已完成的渲染失败。若仍看到这条报错，说明跑的仍是旧代码，请重新加载插件。

怎么确认 LrC 跑的是新版还是缓存旧版插件

Bridge.lua 里有 BRIDGE_VERSION（当前 2026.09.28.1）：

  • 启动 / 停止桥接的弹窗会显示版本号与参数数量，例如 Bridge started (2026.09.28.1) with 107 develop parameters. ...。
  • 任务失败回传网页的红条会带前缀：aiLr Bridge 2026.09.28.1: 原始报错。

判断：弹窗或红条里没有版本号，或红条里出现的是老行号报错，即 LrC 仍在执行旧代码 → 回「文件 > 增效工具管理器」重新加载，或重启 LrC；若重启后依旧，把插件「移除」后重新「添加」aiLr.lrplugin 文件夹。

提示「Lightroom 渲染超时；请确认 LrC 仍打开且 aiLr Bridge 正在运行」

原因：网页轮询等待上限约 4 分钟；期间插件没领取任务、没回传结果，或渲染本身卡住（超大 TIFF、磁盘满、LrC 正在做其它重活）。

处理：确认桥接弹窗还在、插件仍连接；把最长边调小或格式换成 JPEG 再试；检查 %TEMP% 所在磁盘空间；实在不行重启桥接并重启 LrC。

生成方案提示「请先在模型设置中启动模型」

原因：后端要求显式启动模型后才允许推理（HTTP 409）。

处理：右上角「模型设置」→「保存并启动」。若本地模型启动失败，先确认 Ollama 正在运行、模型已 ollama pull；云端模式检查 API Key 与 Base URL 是否有效。

提示「无法解码此 RAW 文件」

原因：LibRaw 不支持该机型 / 该文件版本，或文件损坏。

处理：换一张 RAW 或同机型的另一个文件测试；确认文件完整；必要时先用 LrC / 厂商工具导出 DNG 或 JPEG 再上传。

上传被拒：文件太大

原因：普通图片默认上限 12 MB、RAW 默认上限 100 MB；导出的回传结果默认上限 300 MB。

处理：在 .env 调整 AILR_MAX_IMAGE_MB / AILR_MAX_RAW_IMAGE_MB 后重启后端；或者导出更小的 JPEG。

start.bat 报端口被占用 / 服务起不来

原因：8000 或 5173 被别的程序占用（若是本机已在运行的 aiLr 服务，脚本会直接复用）。

处理：用 start.ps1 -Foreground 看后端日志；确认占用进程（Get-NetTCPConnection -LocalPort 8000）后再决定关闭它还是改端口；-DryRun 可以只看脚本将要执行的命令。

预览图和我预期的调色效果不一样

原因：网页显示的是 LrC 回传的渲染图（「LrC 渲染」标签页），而「原图」标签页是上传前的预览；AI 与网页都不做像素级模拟。

处理：在预览区切换到「LrC 渲染」查看真实结果；若想看得更大、更准，用「LrC 渲染并下载」导出后在 LrC / 看图软件里对比。

LrC 里参数没变化，但网页显示已连接

原因：插件写的是「当前选中照片」；LrC 里换了选中项、切到别的模块、或照片被筛选隐藏，都会导致写入对象与你的预期不一致。文件名不匹配时后端会拒绝创建任务。

处理：在 LrC 中重新选中目标照片，确认网页底部显示的文件名与它一致，然后重新点击应用；查看 LrC 的「历史记录」面板确认写入动作。

换到其它 LrC 版本后个别参数报错

现象：渲染成功，但网页在 Lightroom Classic 区块出现黄色提示（当前 LrC 拒绝了 N 项参数并已跳过）；或红条提示 Lightroom rejected every develop setting (...)。

原因：插件逐项调用 LrDevelopController.setValue。少数参数只在较新的 LrC 版本里存在（镜头校正与变换两组最典型），或照片的 process version 与参数不匹配，宿主就会拒绝该项。2012 后的参数名在插件里会被映射回控制器名（Exposure2012 -> Exposure、Clarity2012 -> Clarity 等 7 项）。

处理：①黄色提示属于正常降级，其余参数已经生效，把不想要的参数在面板里关掉即可；②红条表示全部参数被拒，先在 LrC 里把照片的 process version 更新到当前版本再试；③点「检测 LrC 支持」让插件用只读方式列出当前 LrC 真正接受的参数，不支持的项会被置灰；④仍无法解决时，把带 aiLr Bridge 版本号 前缀的失败原文反馈回来。
